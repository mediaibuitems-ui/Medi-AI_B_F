# AI Analyzer Architecture & Flow (Two-Phase Adaptive Interview)

This document outlines the complete architecture, data flow, and code implementation of the upgraded **Two-Phase Adaptive AI Symptom Analyzer** in the Medi-AI application.

## System Flow Architecture

The AI Analyzer has evolved from a single-shot input form into a dynamic, conversational interview flow. It involves communication between the Flutter frontend, the C# .NET Backend, and the Groq API (using the `llama-3.1-8b-instant` model).

### 1. The Two Phases
- **Phase A (Fixed & Deterministic):** The UI collects demographics, medical context, and a strictly defined set of **Red Flags** (Emergency symptoms). If a red flag is selected, the system bypasses the LLM entirely and immediately routes to Emergency Guidance.
- **Phase B (Adaptive Chat):** If Phase A is clear, the system starts a multi-turn chat interview. The LLM asks one question at a time, reading the patient's actual answer, and deciding the next most relevant question.

### 2. Frontend Flow (Flutter / Dart)
1. **Phase A Collection:** The user accesses the `AiSymptomInputScreen`. They answer basic questions across 3 steps. The `AiSymptomInputController` validates the inputs.
2. **Interview Start:** The frontend POSTs to `/api/analyzer/interview/start`. If it returns `isEmergency: true`, the user is routed to `/emergency-guidance`. Otherwise, they are routed to the `AiSymptomChatScreen`.
3. **Phase B Chat Loop:** The user enters the chat screen. The AI asks questions. When the user replies, the `AiSymptomChatController` POSTs the answer to `/api/analyzer/interview/answer`.
4. **Completion:** The endpoint responds with either `action: "ask"` (with the next question) or `action: "complete"` (with the final parsed analysis).
5. **Results Display:** Upon completion, the user is navigated to `AiSymptomResultScreen`. This screen now features a collapsible **Full Interview Transcript** so the user can review exactly what was discussed, along with a high-level **Interview Summary** generated by the AI.

### 3. Backend Flow (C# .NET)
1. **Session Management:** The state of the interview is managed via a new database entity: `AiSymptomInterviewSession`. This stores the `Transcript` (a JSON array of Q&A) and the `FinalAnalysis`.
2. **Endpoint `/interview/start`:** 
   - Checks for Red Flags.
   - If clear, creates a new `AiSymptomInterviewSession` and saves it to the database.
   - Uses the Groq API to ask the very first follow-up question based on the demographics and context.
3. **Endpoint `/interview/answer`:**
   - Retrieves the session.
   - Performs a **Safety/Emergency Keyword Check** on the user's raw text answer. If an emergency word is found mid-interview, it safely terminates the chat and flags an emergency.
   - Enforces a strict **10-question cap**. If the transcript hits 10 Q&A pairs, the backend forces the LLM to skip asking further questions and output the final JSON analysis.
   - Calls the Groq API passing the *entire* alternating chat transcript.
   - Parses the JSON response to see if it's an `ask` or a `complete` action.
   - Saves the updated transcript to the database.

### 4. Database Persistence (EF Core)
- **Table:** `AiSymptomInterviewSessions`
- **Columns:** `Id`, `UserId`, `CreatedAt`, `CompletedAt`, `Status`, `Demographics`, `Context`, `RedFlags`, `Transcript`, `FinalAnalysis`, `IsEmergency`.

## Code Implementation Summary

### Backend Key Files
- `Models/AiSymptomInterviewSession.cs`: Defines the EF Core model for session tracking.
- `Controllers/SymptomAnalyzerController.cs`: Contains the endpoints `[HttpPost("interview/start")]` and `[HttpPost("interview/answer")]`. It dynamically builds the conversational history array and parses JSON out of the LLM response.

### Frontend Key Files
- `ai_symptom_input_screen.dart` / `controller.dart`: The Phase A collector. Submits to `/interview/start`.
- `ai_symptom_chat_screen.dart` / `controller.dart`: The Phase B chat interface. Submits to `/interview/answer`.
- `ai_symptom_result_screen.dart` / `controller.dart`: Displays the results, parsing the new JSON structure, including the `transcript` and `summary`.
